# Extract live DDL from every `memory/` DB into a tracked `schema/<engine>/` surface, gated by a blocking drift test

**Date:** 2026-10-09 · **Status:** PROPOSED · **Area:** `schema/`,
`helpers/misc/schema_dump.py`, `.opencodereview/rule.json`,
`helpers/misc/review_scan.py`, `Makefile`, `tests/`

Follow-on to `review_scan_followups` (§3: the sqlfluff leg has no live
target). The operator's call: extract DDL for **all** the DBs under
`memory/`, into a plain top-level `schema/<db_type>/` tree, with drift
caught by a **blocking** test in `make qa`.

## 1. Motivation

`review_scan_followups` established that the sqlfluff leg is
structurally dead: no tracked `.sql` exists outside `snapshots/`, and
`snapshots/**` is excluded from review scope. Meanwhile the live schema
lives only inside Python (`helpers/maintenance/rebuild_schema.py` DDL
constants) and inside the DB files themselves, which are gitignored.

That leaves schema review blind in both directions: a PR that changes a
table has no reviewable artifact, and no linter sees the DDL at all.
This proposal makes the live schema a tracked, reviewable, lintable
surface — one file per DB, per engine, regenerated by a helper and
pinned by a blocking test.

## 2. What exists today (verified 2026-10-09)

- **14 DB files under `memory/`**, 8 SQLite + 6 DuckDB (inventoried by
  magic bytes: `SQLite format 3` vs DuckDB's `DUCK` trailer at offset
  4; `memory/graph.duckdb` carries `\x94-\x89Z\x81n\x8f\x0fDUCK`).
- Extraction machinery already exists and is proven:
  `snapshot_db.py:582,601` reads `sqlite_master.sql`,
  `snapshot_db.py:565` uses DuckDB `information_schema`, and it already
  writes three such dumps (`snapshots/parquet/_schema.sqlite.sql` /
  `.duckdb.sql` / `.sources.sql`).
- Those dumps are **backups**, not a review surface: `.opencodereview/rule.json:28`
  excludes `snapshots/**`, and the files are regenerated by the
  snapshot pipeline, so a diff there is snapshot churn, not schema intent.
- The vec0 virtual tables live in `memory/embed_store.db`, deliberately
  NOT in `research.db` (`vec_search.py:60-63`) — a DDL surface has to
  span both.
- `rule.json` has no `schema` glob today, so a new tree needs one.

## 3. Layout

```text
schema/
  sqlite/
    research.sql
    embed_store.sql
    script_search.sql
    doc_search.sql
    memory_search.sql
    convo_search_fts.sql
    md_lint_cache.sql
    corpus.sql
  duckdb/
    graph.sql
    sources.sql
    agent_traces.sql
    convo_search.sql
    model_usage.sql
```

The `<engine>` directory **is** the dialect selector, so no filename
suffix is needed: the sqlfluff leg maps `schema/sqlite/**` → `sqlite`
and `schema/duckdb/**` → `duckdb`, overriding the single `--dialect`
default for files under `schema/`. (This supersedes the
filename-suffix idea from the `review_scan_followups` discussion.)

`schema/` is trackable as-is: `git check-ignore schema/sqlite/research.sql`
is clean, and unlike `memory/` it is not under an ignored **directory**
— which matters, because a negation like `!memory/schema/` cannot
re-include anything beneath an ignored dir (verified in a scratch repo;
the workaround is rewriting `memory/` to `memory/*`). Avoiding that
whole class of problem is a reason to prefer a top-level tree.

## 4. Slices

- **S1 — `helpers/misc/schema_dump.py`**: walk `memory/`, classify each
  DB by magic bytes (never by extension — `graph.xdist-shared.duckdb` is
  a `.duckdb` scratch copy), skip the xdist scratch name, emit one file
  per DB into `schema/<engine>/<stem>.sql`. Ordering: `sqlite_master.rowid`
  (creation order), which `snapshot_db.py:595` already documents as the
  stable choice; header comment names the source DB and a content digest.
  Deterministic output (sorted within a statement, no timestamps beyond
  the source path) so drift means a real schema change.
- **S2 — `make schema-dump`** (regenerate) and **`make schema-fresh`**
  (report drift, no write) — the latter is what the blocking test calls.
- **S3 — Blocking drift test in `make qa`**: `tests/test_schema_drift.py`
  asserts `schema/**` matches the live DBs. **Fails qa** when a tracked
  file is stale (operator decision: blocking, not advisory). It must
  SKIP cleanly when no `memory/` DB exists (a fresh clone has none, since
  `memory/` is gitignored) — otherwise qa is unrunnable off this machine.
  Snapshot restore (`make snapshot-restore`) must regenerate
  `schema/` too, or the test is wrong after a restore.
- **S4 — rule.json**: add `"schema/**/*.sql"` to `include`. Exclusions
  stay untouched; this is additive and narrow.
- **S5 — sqlfluff wiring**: per-engine dialect for `schema/**` in
  `review_scan.py` (the `--dialect` default applies elsewhere). Confirm
  the vec0 virtual-table syntax and DuckDB-specific DDL actually parse
  before promising a clean lint; if a construct does not, the honest
  outcome is a documented skip list, not a disabled leg.
- **S6 — OCR selection**: verify `schema/` changes are selected by
  `make review-patch` and that the teeth assertion is unaffected (no new
  `PRODUCT_FAMILIES` entry — DDL is not a code family).

## 5. Acceptance

- `make schema-fresh` exits 0 on a freshly dumped tree; re-running after
  a `CREATE TABLE` on any inventoried DB makes it exit non-zero with the
  DB named.
- `tests/test_schema_drift.py` goes red on drift (mutation: skip the
  comparison) and skips cleanly with no `memory/` DB present.
- `.venv/bin/python3 helpers/misc/review_scan.py --commit <a schema
  change>` lists the `.sql` file and runs sqlfluff on it with the right
  dialect per engine directory.
- `make review-patch` selects `schema/**` files on a schema-only diff.

## 6. Risks

- **Blocking-in-qa blast radius**: every schema change now fails qa
  until `make schema-dump` runs. That is the intent (a stale DDL file is
  a lie in the review surface), but it will fire on DB rebuilds that do
  not change schema if the emitter is not byte-stable. S1's
  determinism requirement is load-bearing, and the digest header should
  exclude volatile fields (row counts, page stats).
- **Linting real DDL may not be clean**: vec0's `USING vec0(...)` and
  DuckDB's dialect extensions may not parse. Measure before promising;
  a documented skip list beats a silently ignored leg.
- **Data leakage**: DDL can carry sensitive defaults or internal
  endpoint/table names. Review the emitted files before the first commit
  — schema is a publication surface now.
- **14 files churn**: a rename or a new DB produces a diff in a tracked
  tree on every machine that has slightly different DBs. The SKIP
  behavior (S3) keeps qa honest; the churn risk is real but bounded by
  deterministic emission.

## 7. Execution record (2026-10-09, executed same day)

- **S1** `helpers/misc/schema_dump.py` — 13 files dumped (14 DBs
  inventoried; `graph.xdist-shared.duckdb` excluded by name — same bytes
  as `graph.duckdb`, different inode). Magic-byte classification, FTS5/
  vec0 shadow exclusion, `sqlite_master.rowid` / name ordering, digest
  header. Publication-surface review: clean — no secret literals, only
  `DEFAULT('NSE')` and `CURRENT_TIMESTAMP`; house CHECK-comment context
  came along as review value, not leakage. Found and fixed en route:
  `duckdb_views()` selects `view_name`, not `table_name`.
- **S2** `make schema-dump` / `schema-fresh` — drift exits 1 (mutation:
  appended a comment line to `corpus.sql` → stale, named; `schema-dump`
  restores clean).
- **S3** `tests/test_schema_drift.py` — 3 tests: blocking match, orphan
  class, missing-file class; SKIP when no `memory/` DB (fresh clone).
  Mutation M1 (stale file) red. The tests caught a real bug:
  `check()` called `.relative_to(REPO_ROOT)` on scratch out-dirs —
  fixed with a repo-relative-or-absolute `disp()`.
- **S4** rule.json gains `schema/**/*.sql` (additive; excludes
  untouched). `_families()` resolves `schema/`; snapshots stay excluded.
- **S5** per-engine sqlfluff: `_sql_engine()` maps the engine directory
  to the dialect; measured 6 unparsable sections (5× fts5 `UNINDEXED`,
  1× vec0 `FLOAT[512]`/`distance_metric`) → `PRS` suppressed inside a
  `USING fts5(`/`USING vec0(` window (the DDL is generated, so no inline
  noqa is possible). Mutations: routing dead → red; PRS filter removed
  → red.
- **The golden caught a vacuous-0 again**: first end-to-end run on the
  schema commit itself reported `sqlfluff: ran (0 kept)` while the raw
  file carried 298 violations — sqlfluff 4.x emits `start_line_no`,
  the leg read `line_no`. Fixed (`start_line_no` with fallback), pinned
  (mutation M5 red). The roster then showed ~300 findings — layout/
  case/length noise from the DDL inheriting Python-source indentation —
  resolved by the `schema/.sqlfluff` format contract (layout family +
  CP03/RF04/RF06 excluded; per-engine dialect configs for bare manual
  runs). Leg on all 13 dumps after: **9 kept**, all AM04/RF02/RF03 on
  the `sources.sql` views — the structural signals worth surfacing.
- **Not landed, deliberately:** no `doc/templates/` seed — the dumps
  are generated, so the format contract lives in `schema/.sqlfluff`,
  the emitter docstring, and a pointer from `doc/design/db_schema.md`.
- Operator choices honored verbatim: top-level `schema/<engine>/`,
  blocking qa gate, directory-as-dialect. Suite at close: 63 tests
  green (review_scan 37 + schema_drift 3 + review_tooling 23), ruff +
  markdown-lint clean.
