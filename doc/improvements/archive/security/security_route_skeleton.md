# Route skeleton — publish the surface shape, keep the verdicts local

**Date:** 2026-09-28 · **Status:** EXECUTED (completed.md #8171) · **Follows:**
`doc/improvements/archive/security/post_review_api_reaudit.md` (security-coverage
arc #247b, S3 — the coverage ledger)

## 1. Motivation

Arc #247b S3 replaced a prose security snapshot with a machine-checked
coverage ledger, `doc/local/security/coverage-ledger.json`, and
`check_coverage_ledger` enforces three conditions against it: **completeness**
(every route in `app.py` has >=1 row), **freshness** (a per-handler-body
fingerprint, fatal under `--strict`), and **consistency** (no row naming a route
that no longer exists).
The ledger is gitignored **by design** — `doc/local/` is "private local notes
(never for git)" — and that design has a consequence nobody wrote down:

> On any fresh clone, `DEFAULT_LEDGER.is_file()` is False, the check returns an
> **advisory skip**, and its absence is a *success*.

So the completeness half of #247b holds for exactly one person. A collaborator —
or a future clone of this repo — can add a 39th route to `app.py` with no
security review whatsoever and their gate stays green. That is the precise
failure #247b was created to prevent (13 routes shipped post-snapshot with no
review), reopened for everyone but the operator. The arc's own success
criterion tested the loop on the operator's machine, which is why this went
unnoticed.

## 2. Why the ledger itself cannot simply be tracked

The ledger is an attack-surface map. Its `verdict` columns name routes that lack
authentication, lack byte caps, and lack page-count caps — e.g. *"no auth on
mutating POST (SEC-5, deploy-gated, Phase 4 dormant)"*, *"r.read() unbounded,
no byte cap"*. Publishing those as JSON keyed by surface and attack class is a
materially different artifact from an arc document that discusses the classes in
prose, and trivially scrapeable.

**The repository is public**: `api.github.com/repos/arun-ramakrishnan/findata-graph`
answers `200` unauthenticated. So the ledger stays operator-local. The fix is to
split the claim, not to weaken the sensitivity call.

## 3. Design / Slices

- **S1 — `helpers/validators/route_skeleton.py`** (new). `route_inventory` (ast,
  so `methods=`-carrying decorators are counted, not just literal paths),
  `load_skeleton`, `check`, `seed`, plus a `--write` CLI. Four fatal conditions:
  **UNLISTED** (route in `app.py`, absent from the skeleton), **STALE** (skeleton
  entry with no matching route), **METHOD CHANGE** (read-only becoming mutating
  is security-relevant even though no path appeared), and **absent/malformed
  skeleton** — which is fatal, *not* a skip, because visibility of the absence
  is the entire point.
- **S2 — `doc/security/routes.json`** (new, tracked, generated by `--write`).
  `schema: route-skeleton.v1`, 38 routes as `{path, methods}`. **The disclosure
  argument: this file contains nothing that tracked, public `app.py` does not
  already state** — the paths and methods are string literals in the source. What
  it adds is a *commitment device*: the surface is enumerated, so changing it is a
  deliberate diff rather than an accident.
- **S3 — wired into `static_checks.py`** as `("Route skeleton", check_route_skeleton)`,
  adjacent to the ledger check.

## 4. What is deliberately NOT published

| Column | Where it lives | Why |
|---|---|---|
| `attack_class`, `verdict` | coverage ledger (local) | names unpatched weaknesses per route |
| `reviewed`, `method` | coverage ledger (local) | who reviewed what, when, how |
| `fingerprint` | coverage ledger (local) | per-handler review-freshness hash |

So **this check is deliberately weaker than the ledger.** It enforces
completeness and shape; it never asserts review freshness. A route can be listed
in the skeleton and be entirely unreviewed, and the gate will pass. That
limitation is the price of publishing, and it should be stated in the file itself
so nobody later reads a green skeleton as "reviewed". The ledger remains the only
artifact that can say "reviewed", and only the operator can read it.

## 5. Acceptance

- `make static-checks` shows `Route skeleton` agreeing with `app.py` (38 routes).
- **Mutation-verified, all three fatal**:
  - append a new `@app.route` to `app.py` -> `UNLISTED`, rc 1
  - flip an existing route to `methods=["POST"]` -> `METHOD CHANGE`, rc 1
  - move `routes.json` aside -> fatal missing-skeleton, rc 1 (explicitly *not* a skip)
- Skeleton regenerates cleanly: `python3 helpers/validators/route_skeleton.py --write`.
- `doc/security/routes.json` contains no `verdict` / `attack_class` / `fingerprint` key.

## 6. Residual risk (accepted)

- A **clone on an older commit** has no skeleton and fails the gate until
  `--write` is run. Intended: loud beats silent, and the remedy is one command
  named in the failure text.
- Someone can satisfy the check by running `--write` reflexively. The skeleton
  cannot enforce that a *review* happened — only that a *decision* was recorded.
  The gate's job ends there; the operator's judgement does not.
- Fingerprint-based freshness remains operator-only, so handler edits are still
  caught for the operator and not for anyone else. Closing that needs the
  fingerprint tracked, which re-opens §2. Deferred, not solved.
